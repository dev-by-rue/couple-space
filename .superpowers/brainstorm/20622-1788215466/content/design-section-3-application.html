Design §3 — Application & token mapping

How the brand lands in the web app. Approve to finish design sections, or request changes.

Where it lives

  • Update apps/web/app/globals.css :root and .dark CSS variables (existing shadcn tokens — no new color API).
  • Replace Nunito Sans with Figtree via next/font in layout.tsx; keep Geist Mono for --font-mono.
  • Light + dark both first-class; theme toggle already supported by .dark variant.

Token roles

  • primary / ring → soft teal (CTAs, links, focus)
  • secondary / accent → soft sage (secondary buttons, chips, soft highlights)
  • background / card → warm ivory / warm charcoal
  • muted / border / input → warm stone neutrals (structure only)
  • destructive → independent red (errors, destructive confirms)
  • sidebar-* → same brand hues as main surface/primary

Out of scope for this brand pass

  • Marketing landing redesign, illustration, or logo mark
  • Per-page custom palettes or gradient systems
  • Changing component structure — only tokens + font wiring

Acceptance checks

  • Login and auth screens look branded in light and dark
  • Primary vs secondary buttons are visually distinct (teal vs sage)
  • Body/UI text renders in Figtree; no Nunito remaining
  • Text/icon contrast remains usable on ivory and charcoal (spot-check CTAs and muted text)
