# P1-17 · CI

[← Phase 1](../phase-1-mvp-1.md) · Size **M** · After: [P1-14](P1-14-email-nudges.md) · Next: [P1-18](P1-18-error-monitoring.md)

**Goal:** every push and PR to `main` runs install, type checks, lint, unit tests and API e2e tests
(against a real Postgres) on GitHub Actions. `main` is protected so it only accepts green PRs.

**Done when:**

- `.github/workflows/ci.yml` runs `pnpm install --frozen-lockfile`, `turbo run check-types lint test`, and the API e2e suite.
- `turbo.json` has `lint` and `test:e2e` tasks, and the root `package.json` has matching scripts.
- Migrations run against the CI database before e2e, so a broken migration fails CI.
- Branch protection on `main` requires the `ci` check.

### Notes

- **`lint` doesn't exist in `turbo.json` yet**, so `turbo run lint` fails today. Step 1 adds it. The other
  guides use `pnpm check-types && pnpm test` for that reason; after this task you can use `pnpm lint` as well.
- **The domain package has no `lint` script.** Turbo skips packages without the script, so that's fine.
  Add oxlint there later if you want.
- **Node version:** `@types/node` is `^24`, so CI uses Node 24. Add an `.nvmrc` with `24` so local, CI
  and Railway agree. Check that Railway's Railpack picks up `.nvmrc`; it reads `engines` and `.nvmrc`.
- **Branch protection means you'll work through PRs.** CLAUDE.md says plans and docs go straight to
  `main` when you ask. With protection on, either allow yourself to bypass (admins) or use PRs for docs
  too. Your call; the step below shows the admin-bypass setting.

## Step 1 · Turbo and root scripts

### `turbo.json` (change)
**Before**
```json
    "test": {
      "dependsOn": ["^build"],
      "outputs": []
    }
  }
}
```
**After**
```json
    "test": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "lint": {
      "outputs": []
    },
    "test:e2e": {
      "dependsOn": ["^build"],
      "cache": false,
      "env": ["DATABASE_URL", "JWT_SECRET"]
    }
  }
}
```
`test:e2e` isn't cached, because its result depends on the database, not only the files.

**Before**
```json

    "test": "turbo run test"
```
**After**
```json
    "check-types": "turbo run check-types",
    "lint": "turbo run lint",
    "test": "turbo run test",
    "test:e2e": "turbo run test:e2e"
```

## Step 2 · The workflow

### `.github/workflows/ci.yml` (new)
```yaml
name: ci

on:
  push:
    branches: [main]
  pull_request:

# A newer push to the same branch cancels the older run.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  ci:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    services:
      postgres:
        image: postgres:15
        env:
          POSTGRES_USER: couple
          POSTGRES_PASSWORD: couple
          POSTGRES_DB: couple_space_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U couple"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10

    env:
      DATABASE_URL: postgres://couple:couple@localhost:5432/couple_space_test
      # Test-only value; not a secret.
      JWT_SECRET: ci-only-secret-at-least-32-characters-long
      SANDBOX_AUTO_VERIFY: "true"
      TURBO_TELEMETRY_DISABLED: "1"

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        # Reads the version from "packageManager" in package.json.

      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Type check, lint, unit tests
        run: pnpm turbo run check-types lint test

      - name: Migrate and seed the CI database
        run: |
          pnpm --filter @couple-space/database migrate
          pnpm --filter @couple-space/database seed

      - name: API e2e tests
        run: pnpm turbo run test:e2e --filter=@couple-space/api
```
Postgres 15 matches your local Homebrew `postgresql@15`. Change the image if Railway runs a different
major version (check the Railway Postgres service), so CI tests what production runs.

`drizzle.config.ts` loads `../../.env` with dotenv, which doesn't exist in CI. That's fine: dotenv
doesn't override variables that are already set, and the job `env` sets `DATABASE_URL`.

`apps/web` `check-types` runs `next typegen`, which needs nothing from the network. If it ever needs
`NEXT_PUBLIC_*` values at build time, add them to the job `env` with dummy values.

## Step 3 · Make the e2e suite CI-safe

E2E tests build the full `AppModule`. Check these before the first run:

- **`MailModule` creates an SMTP transport at startup.** `nodemailer.createTransport` doesn't connect
  until it sends, so the defaults (`127.0.0.1`) are fine as long as no e2e test sends mail. A test that
  registers a user with `SANDBOX_AUTO_VERIFY=true` returns before sending.
- **`PushService`** with no VAPID keys turns sending off (per the `env.ts` comment). Good.
- **P1-10's `assertMailConfigured`** only runs in `main.ts` with `NODE_ENV=production`; e2e tests don't
  call `main.ts`.
- **Rate-limit e2e (P1-15):** each test creates a new app, so in-memory counters don't leak between tests.

If tests share the database and leave rows behind, make them create unique emails
(`` `e2e-${randomUUID()}@example.com` ``) instead of truncating tables.

## Step 4 · Branch protection (GitHub settings, no code)

Repository → Settings → Rules → Rulesets → New branch ruleset:
- **Target:** `main` (default branch).
- **Require a pull request before merging:** on. Required approvals: 0 (it's just you).
- **Require status checks to pass:** add `ci` (it appears after the first run).
- **Block force pushes:** on.
- **Bypass list:** add yourself (Repository admin) if you want to keep committing docs straight to `main`.

Or with the CLI after the first CI run (classic branch protection):
```sh
gh api -X PUT repos/dev-by-rue/couple-space/branches/main/protection \
  -f required_status_checks.strict=true \
  -f 'required_status_checks.contexts[]=ci' \
  -F enforce_admins=false \
  -f required_pull_request_reviews.required_approving_review_count=0 \
  -F restrictions=null
```
`enforce_admins=false` is the CLI version of the admin bypass.

## Verification
1. Locally: `pnpm lint` works from the root; `pnpm test:e2e` passes against your local DB.
2. Push a branch and open a PR → the `ci` job runs and all steps go green in about 3–5 minutes.
3. Break a type on the branch → CI fails at "Type check, lint, unit tests"; fix it.
4. Add a deliberately broken migration on a scratch branch → CI fails at "Migrate"; delete the branch.
5. After setting protection: a direct `git push origin main` is rejected (unless you're on the bypass list).
