# Code conventions — apps/web

Follow these for all new and edited code. `components/ui/` is the exception: it is generated by the shadcn CLI — leave its style as generated.

## Functions

- Components, hooks and helpers are **function declarations**: `export function Name() {}`.
- Arrow functions only inline (callbacks, `.map()`, event handlers, `select`).
- **Named exports** everywhere. `export default` only where Next.js requires it (`page.tsx`, `layout.tsx`, etc.).

## Props

- Declare props as a **`type`**, named `<Component>Props`, directly above the component. Never `interface`, never inline object types.
- Export the props type only if another file imports it.
- Extend with `&`, e.g. `type PillProps = React.HTMLAttributes<HTMLSpanElement> & { phase: SessionViewerPhase };`
- Always wrap in **`Readonly<…>`** in the signature: `({ session }: Readonly<ConversationCardProps>)`.
- Document individual props with a `/** … */` comment on the field (shows on hover), not with `@param` on the component.

```tsx
type ConversationCardProps = {
  /** The session to summarise, as returned by `GET /sessions`. */
  session: SessionListItem;
  /** Extra classes merged onto the card. */
  className?: string;
};

export function ConversationCard({
  session,
  className,
}: Readonly<ConversationCardProps>) {
```

## Doc comments (TSDoc — tsdoc.org)

Only add a doc comment when it explains something the code doesn't (the _why_, a caveat, a safety rule). When there is one, use this structure:

1. **Summary** — one sentence, ending with a full stop.
2. Blank ` *` line.
3. **`@remarks`** — the why / caveats (optional).
4. **`@param name - description`** — note the hyphen (functions and hooks only).
5. **`@returns description`** (functions and hooks only).
6. **`@throws`** if it can throw (optional).
7. Do not include the task reference in the comment, it should be written as production, if amendments are needed to the same component and it's tsdocs. Amend/overwrite at that time.

Functions and hooks:

```ts
/**
 * Orders hub sessions so the ones needing the viewer come first.
 *
 * @remarks
 * Ties are broken newest first. Returns a new array — cached data must not be mutated.
 *
 * @param sessions - Sessions from `GET /sessions`, in any order
 * @returns A new, sorted array
 */
```

Components: summary + optional `@remarks` only. **No `@param` / `@returns`** on components — props are documented on the props type fields, and every component returns JSX.

```tsx
/**
 * A hub card linking to one conversation.
 *
 * @remarks
 * The whole card is the link; the CTA is a styled `<span>`, so no interactive
 * element is nested inside the link.
 */
```

- File-level comments end with `@packageDocumentation`.
- Use `{@link Name}` to reference other symbols, backticks for code.
- No trailing whitespace on ` *` lines; no empty ` *` line before `*/`.

## Files and folders

- File names in **kebab-case**: `invite-partner-form.tsx`.
- Molecules and organisms live in their own folder: `components/molecules/<name>/<name>.tsx`.
- Imports use the `@/` alias, not relative `../` paths.
- `import type` for anything used only as a type.

## Formatting

- Prettier config is at the repo root (`/.prettierrc`): double quotes, semicolons, trailing commas, 2-space indent. Format on save.
